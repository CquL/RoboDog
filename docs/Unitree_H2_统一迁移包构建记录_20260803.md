## 关键实现决定

### 1. 目标机配置与交付物分离

`config/deployment.env.example` 是模板；目标机复制为 `config/deployment.env` 后再配置。生成的 `state/` 和 `deployment.env` 不进入 SHA256 清单，上传脚本检测到它们时会拒绝迁移，避免把旧 H2 的网卡/domain 带到新机器人。

### 2. 同时覆盖 Bridge 与 HAL 的 DDS 配置

只设置环境变量不足以保证换机生效：Bridge 参数文件和 HAL YAML 都可能保留 `eth0/domain 0`。`h2_bundle.sh start-imu` 会：

- 给 Bridge 显式传入 `-p dds_interface:=...` 与 `-p dds_domain:=...`；
- 生成目标机专用 safe/motion YAML；
- 将两份 YAML 以只读 bind mount 覆盖镜像内配置。

### 3. 迁移前验证实际 PC1 路由

`check-host` 不只确认网卡存在，还要求网卡 UP、有 IPv4，并检查 `ip route get PC1` 的实际 `dev` 与 DDS 网卡一致。外接 USB/Wi-Fi 远程链路不能误当作 PC1 DDS 链路。

### 4. 持久容器与权限边界

IMU Bridge 容器使用 host network、只读根文件系统、capabilities 全部移除、`no-new-privileges` 和 `unless-stopped`。同名容器不属于本镜像标签时，脚本拒绝删除。

Bridge 进程本身只订阅状态，但整个镜像还包含 HAL 控制程序；拥有 Docker 权限的人仍可显式执行控制命令，因此文档没有把“整个容器”描述为只读能力。

### 5. 上传过程不合并旧目录

`transfer_to_h2.ps1` 先校验本地完整清单，再上传到带时间戳的临时目录，在 H2 远端执行 `bash h2_bundle.sh verify`，通过后才改为最终目录。最终目录已存在时停止，不覆盖、不递归删除，也不把新旧文件静默合并。

### 6. 默认拒绝未验收动作并检查常见并发进程

迁移包的 motion YAML 保留速度控制，但将 `allow_state_changing_actions` 默认设为 `false`；`stop_move` 仍由 HAL 作为安全动作允许。`preflight` 在读取 FSM 前检查容器内常见 H2 测试/控制进程名；该检查不能证明遥控器、宿主机或其他 DDS 参与者不存在，因此现场仍要人工确认独占发送者。

`start-imu` 会启用 Docker 服务开机启动；容器继续使用 `unless-stopped`。导航算法若在另一容器消费 IMU，需要同样使用 host network、ROS domain 20 和兼容 RMW。

## 当前功能范围

已随包交付：

- `rt/lowstate.imu_state -> /h2/imu/pelvis`；
- `rt/secondary_imu -> /h2/imu/torso`；
- `RobotHardwareInterface -> UnitreeH2 -> LocoClient` 底层控制链；
- FSM=601 只读门禁、zero-stop、短时单轴速度测试程序。

未随包交付：雷达/深度相机驱动、点云 Bridge、SLAM/导航、生产型控制器、自动 FSM 状态机。
