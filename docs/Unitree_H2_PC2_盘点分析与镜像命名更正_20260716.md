- `eth1=192.168.124.162/24`；`192.168.124.161` 与雷达检查目标
  `192.168.124.20` 在采集时均未完成邻居解析。
- 没有默认路由，当前不能依赖 PC2 在线拉取镜像或软件包。
- 已安装 ROS 2 Humble、CycloneDDS，当前
  `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`。
- 已发现 `/opt/unitree_robotics`、
  `/opt/unitree_robotics/lib/cmake/unitree_sdk2` 和
  `/usr/local/lib/cmake/unitree_sdk2`；SDK2 很可能已原生安装，但需继续核对两处
  CMake 包、真实库和 ABI。
- PC2 当前没有安装 Docker，也没有 NVIDIA GPU/驱动工具。
- 原厂/交付栈正在运行 `master_service`、`unitree_slam`、`dog_cmd eth0`、
  `sport_switch`、`bms_ctr` 等。名称中出现 Go2/B2/dog_control 只能说明供应商复用
  软件，不据此判断装错；当前不得停止或替换这些进程。
- 存在 RSLidar、Hesai、Livox、LIO-SAM 软件痕迹，但没有足够证据证明对应传感器
  当前在线。尤其 `192.168.124.20` 当时不可达。
- `shoujuan_server.service` 处于 failed，下一轮只读查看状态和日志，不重启。

## Docker 基础关系与命名更正

本地 H2 镜像确实以 `jezetek:navigation_system_amd64` 为基础：

```text
base image ID = sha256:6429796814f0fdd7a54e7ba2ad2e3387a0342037cb1da874a604f72cc34fc257
H2 image ID   = sha256:b4e6c8661d1a6b815e3dd454d40ba177d1effdbbc3f352cbfa915ce66619f727
base layers   = 17
H2 layers     = 21
common prefix = 17 layers
SDK2 commit   = 21d0a3b2c46ee48c8fdf2783becb6be3beb0a59b
```

因此 H2 是在同一通用 Ubuntu 22.04/ROS2 Humble 基础上增加 SDK2、完整
`robot_hardware`、配置和测试程序得到的新派生镜像，不是复用 X30 厂商驱动。

按用户要求完成命名调整：

```text
旧标签（已删除）：robodog_unitree_h2:amd64-offline
当前标签：        unitree_h2:amd64-offline
当前容器名：      unitree-h2-hal
```

本次采用 Docker retag，镜像内容和 ID 不变。新标签下重新执行断网、只读、
drop-all-capabilities Factory 合同测试，输出 `UNITREE_H2_FACTORY_CONTRACT_OK`；
Compose 解析通过。未来构建脚本和 Compose 已统一使用新名称。

## 当前部署决定

PC2 没有 Docker，所以本轮不上传约 3.5 GB 的 H2 镜像，也不擅自安装 Docker。
安装 Docker 会改变 PC2 的系统包、服务、网络规则和启动状态，需要单独评审和用户
授权。现阶段优先使用已有 ROS2/SDK2 环境完成只读兼容性核对。
