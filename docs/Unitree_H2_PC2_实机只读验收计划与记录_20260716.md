## 2. 官方架构与资料结论

- H2 EDU 才标注支持二次开发；PC1 是原厂运动控制单元，PC2 是用户开发单元。
- H2 实机公共通信底座是 CycloneDDS。SDK2 可直接使用 DDS，不要求上层必须运行
  ROS 2；ROS 2 Humble 是 Ubuntu 22.04 上的兼容接入层。ROS 1 `unitree_ros` 主要用作
  模型/仿真资料，不作为 H2 实机控制基座。
- 2026-07-16 在线官方 HEAD 与本地固定快照一致：
  - `unitree_sdk2`: `21d0a3b2c46ee48c8fdf2783becb6be3beb0a59b`
  - `unitree_ros2`: `668d1ec5a05d1c38d3306bdca7d59f2ba3581a88`
  - `unitree_sdk2_python`: `e4cd91f051aaa77a70600e3d2bf7f50889db1980`
- 当前 H2 官方资料可确认的状态 topic 是 `rt/lowstate` 与 `rt/secondary_imu`；
  `rt/lowcmd` 是危险的低层电机命令输出，不属于本阶段输入。
- 产品页只确认宽视场双目相机，没有确认 Livox/MID360 为 H2 标配。相机、雷达、
  odometry、TF、BMS 独立 topic 必须从交付机和供应商资料确认。

## 3. 抽象控制协议的当前匹配

Factory 使用 `robot_model: unitree_h2` 创建 `UnitreeH2`。三接口匹配如下：

| 项目抽象接口 | H2 SDK2 实现 | 当前保护 |
|---|---|---|
| `initRobotHardware()` | `ChannelFactory::Init(domain, NIC)` → `LocoClient::Init()` → `SetTimeout()` → `GetFsmId()` | 初始化阶段仅查询 FSM |
| `writeRobotVelocityCommand()` | `SetVelocity(vx, vy, omega, duration)`，官方 API ID `7105` | 有限值检查、限幅、短 duration、超时看门狗；默认拒绝非零 |
| `writeActionCommand(stop_move)` | `StopMove()`，实质为 `SetVelocity(0,0,0)` | 始终明确处理，但仍属于控制写入 |
| `writeActionCommand(stand_up)` | `StandUp()` / FSM 4 | 默认关闭 |
| `writeActionCommand(prepare_motion)` | `Start()` / FSM 601 | 默认关闭 |
| `writeActionCommand(damp)` | `Damp()` / FSM 1 | 默认关闭；不等于 `lie_down` |
| `writeActionCommand(squat)` | `Squat()` / FSM 2 | 默认关闭 |
| `writeActionCommand(sit)` | `Sit()` / FSM 3 | 默认关闭 |
| `writeActionCommand(lie_down)` | 不做猜测映射，返回“不支持” | 防止把 `Damp()` 错当趴下 |

官方接口证据：

- [H2 Loco API](https://github.com/unitreerobotics/unitree_sdk2/blob/21d0a3b2c46ee48c8fdf2783becb6be3beb0a59b/include/unitree/robot/h2/loco/h2_loco_api.hpp)
- [H2 LocoClient](https://github.com/unitreerobotics/unitree_sdk2/blob/21d0a3b2c46ee48c8fdf2783becb6be3beb0a59b/include/unitree/robot/h2/loco/h2_loco_client.hpp)
- [H2 高层示例](https://github.com/unitreerobotics/unitree_sdk2/blob/21d0a3b2c46ee48c8fdf2783becb6be3beb0a59b/example/h2/high_level/h2_loco_client_example.cpp)

结论：抽象接口到 H2 SDK2 的代码匹配已完成并通过离线编译/Factory 测试；尚未验证这台
H2 的真实网卡、服务端 API、FSM、坐标方向、速度单位/范围和返回码，因此不能宣布
“实机控制就绪”。

## 4. 输入桥当前状态

控制输出 HAL 已有，`unitree_h2_sensor_bridge` 还没有实现。当前官方可确认：

| DDS 输入 | 当前 IDL 信息 | 计划统一输出 |
|---|---|---|
| `rt/lowstate` | mode、1 ms tick、pelvis IMU、`MotorState[35]`、遥控器 40 字节、reserve、CRC | `JointState`、pelvis `Imu`、`RobotStatus` |
| `rt/secondary_imu` | torso IMU | torso `Imu` |
| Loco RPC `GetFsmId`/返回码 | 运动服务状态与命令确认 | `RobotStatus`、diagnostics |

独立 BMS、odometry、相机、雷达、TF 和安全状态 topic 暂列为“待实机发现”，不沿用
X30 名称。详见 `unitreeH2/H2_INPUT_AND_BRIDGE_CONTRACT.md`。

## 5. Docker 与 X30 边界

H2 Docker 是 2026-07-15 新写的独立方案：

- 基于共享的 `jezetek:navigation_system_amd64`（Ubuntu 22.04 / ROS 2 Humble）；
- 增加固定版本 SDK2 与完整 `robot_hardware`；
- 当前只包含 H2 HAL、配置和合同测试，不含传感器桥、导航算法或自动启动入口；
- 默认进入 Bash，不自动发现 DDS、不自动发控制；Compose 使用 host network，
  `privileged: false`、drop all capabilities、只读根文件系统。

`deep_robotics_x30/docker/x30_livox_ros2_transfer.tar.gz` 是 X30 专用源码传输包，不是
Docker save 镜像：846,791 字节，SHA-256
`BF76C3BA07179EE6CFC446AA088C74E3C3E158047776AA6CE79BD0DE7033EA28`。它包含 X30
MID360、Livox、Yesense `/dev/ttyS0`、`/x30/*`、原厂停启脚本和 plane segmentation，
不能在 H2 上直接运行。两种机器人只共享基础镜像、标准 ROS 2 消息合同和真正通用的
算法层，不共享厂商传感器/控制包。

## 6. 本轮实际修改与验证

1. 发现旧探针虽然称“只读”，实际会自动发零速度/`StopMove()`，析构也会写停止。
2. 已改为：默认或 `--read-only` 只初始化并 `GetFsmId`；只有显式 `--zero-stop` 才发
   零速度和 `StopMove()`。
3. `UnitreeH2` 现在只在该对象实际成功发过控制命令后，析构才补发 `StopMove()`；
   纯只读查询退出时不写控制。
4. 新增 PC2 第一轮只读脚本：`unitreeH2/remote/00_pc2_read_only_inventory.sh`。
5. 用 Docker `--network=none` 重编译 SDK2 + 四个 HAL 适配器，CTest 1/1 通过；
   `UNITREE_H2_FACTORY_CONTRACT_OK`。
6. 当时构建标签：`robodog_unitree_h2:amd64-offline`（已于 2026-07-16 更名并废弃）；当前规范标签：`unitree_h2:amd64-offline`，amd64，镜像 ID
   `sha256:b4e6c8661d1a6b815e3dd454d40ba177d1effdbbc3f352cbfa915ce66619f727`。

上述验证没有连接 H2，没有发送零速度、`StopMove()`、非零速度或动作。

## 7. 下一步执行顺序

### 阶段 1：PC2 系统只读盘点（现在）

把 `unitreeH2/remote/00_pc2_read_only_inventory.sh` 上传到 PC2，然后只运行：

```bash
bash 00_pc2_read_only_inventory.sh
```

把完整终端输出保存/回传。脚本不使用 sudo，不安装软件，不改网络，不启停服务，不启动
容器，不枚举或写入控制 topic。

### 阶段 2：审计 PC2 输出

确认真实网卡、ROS 2/SDK2/CycloneDDS 版本、原厂服务、Docker/GPU、传感器设备和已有
工作区。此时仍不升级系统；登录提示的 545 个更新不能直接安装，特别不能擅自升级
实时内核、驱动、CUDA、CycloneDDS 或厂商包。

### 阶段 3：只读 DDS/ROS 2 发现

根据阶段 1 确认的环境，枚举 topic 名称、类型、频率和发布者；只订阅
`rt/lowstate`、`rt/secondary_imu` 等状态，不发布 `rt/lowcmd`，不停止 `sport` 服务。

### 阶段 4：只读 FSM 验证

把配置中的 `network_interface_card_name` 从占位 `eth0` 改为已确认的 H2 内部有线网卡，
在 host network 容器中运行 `robot_test_unitree_h2 <config> --read-only`。该阶段只调用
`GetFsmId`，不运行 `--zero-stop`。

### 阶段 5：传感器桥与离线回放

冻结实际 topic/IDL/QoS/TF 合同，实现 `unitree_h2_sensor_bridge`，先录制无运动数据，
在断网容器中做时间戳、坐标、掉帧、超时和重启测试。

### 阶段 6：受控零速度与后续运动

只有供应商/现场安全负责人确认、保护架/清场/遥控器/硬件急停就绪后，才显式运行
`--zero-stop`。非零速度和状态动作仍需另一次审查后逐项开放；当前不执行低层
`rt/lowcmd`。

## 8. 禁止事项

- 不执行 `apt upgrade` 或内核/驱动升级。
- 不停止或 kill 宇树原厂运动、遥控器或安全服务。
- 不上传/启动 X30 传感器容器。
- 不把 `rt/lowcmd` 当普通速度接口。
- 不在首轮运行官方 ankle swing 低层示例。
- 不把软件 `StopMove()` 当作物理急停。
