## 4. X30 三个抽象接口现状

`RobotHardwareInterface` 本身不需要修改。

| 接口 | X30 当前实现 | 结论 |
|---|---|---|
| `initRobotHardware()` | UDP socket、连接确认、心跳、速度 watchdog | 已实现 |
| `writeRobotVelocityCommand()` | 当前配置使用原厂 `0x150` 导航速度包发往 `105:43897` | 已实现并有实机运动验证 |
| `writeActionCommand()` | 停止、起停、站立/趴下切换、行走、L 行走、山地 | 部分原厂动作已实现 |

当前实现是对原厂 UDP 协议的封装，不是链接一个原厂 C++ SDK。

尚未实现：

```text
ACTION_GAIT_STAIRS
ACTION_GAIT_STAIRS_ACCUMULATED
ACTION_GAIT_STAIRS_45
```

当前测试还明确检查 `ACTION_GAIT_STAIRS_45` 不存在，防止在地形联锁未完成时
误发 `0x3101040B`。

## 5. 当前能否测试 45 度楼梯

结论：现在不能直接发送 45 度楼梯动作或非零速度。

需要区分：

```text
原厂楼梯链
  原厂 ROS1 高度图、plane_seg、gridmap_port 继续运行
  当前被动 Docker 模式没有破坏该链
  具备继续做只读门槛检查的条件

Docker 自研楼梯链
  当前只收到点云、IMU、腿部里程计
  尚未在线生成高度图、quadrangels 和 103:49999 地形流
  尚未完成
```

45 度楼梯要求：

```text
机器人静止
-> 激光里程计开启
-> 高度图模式进入累积帧 20
-> /plane_seg/quadrangels 持续新鲜
-> 105 到 103:49999 TCP 地形流持续新鲜
-> 发送 0x3101040B
-> 确认 /robot_gait_state=8
-> 才允许受保护的非零速度
```

当前 HAL 没有完成上述状态机，也没有订阅
`/height_map_mode_state` 和 `/robot_gait_state` 进行楼梯联锁。

## 8. 2026-07-30 实测结果

### 8.1 ROS2 Docker 点云

通过 105 上的只读转发节点，将原厂 ROS1 `/lidar_points` 转发为 106 Docker
中的 ROS2 `/x30/lidar_points`。离线 rosbag 在 Foxglove 中已经正常显示：

```text
topic: /x30/lidar_points
type: sensor_msgs/msg/PointCloud2
frame_id: lidar_link
points per frame: approximately 80000
```

离线 bag 额外加入的 `viewer_world -> lidar_link` 零位姿静态 TF 只用于
Foxglove 显示，不参与机器人定位、地形计算或控制。

### 8.2 原厂地形链基线

机器人保持静止且未切换 45 度楼梯步态时，在 105 实测：

```text
/height_map_mode_state = 3
/plane_seg/quadrangels = approximately 10.05 Hz
/plane_seg publisher = /plane_seg
/plane_seg subscriber = /gridmap_port
/robot_basic_state = 0
/robot_gait_state = 0
192.168.1.105 -> 192.168.1.103:49999 = ESTAB
```

本轮已经验证：

```text
ROS2 Docker 能收到并显示点云
原厂 height-map/plane-seg 处理链仍在运行
quadrangels 持续输出
gridmap_port 持续订阅
105 到 103 的 TCP 地形连接正常
```

本轮尚未验证：

```text
45 度楼梯请求后 height_map_mode_state 是否进入 20
45 度楼梯请求后 robot_gait_state 是否进入 8
模式切换期间 quadrangels 和 TCP 是否持续新鲜
RobotHardwareInterface 的 45 度楼梯动作映射
任何非零速度楼梯运动
```

### 8.3 原厂遥控器普通楼梯步态切换

机器人保持零速度，通过原厂遥控器选择“楼梯模式”后实测：

```text
/robot_gait_state = 6
/height_map_mode_state = 3
/plane_seg/quadrangels = approximately 10.00 Hz
192.168.1.105 -> 192.168.1.103:49999 = ESTAB
```

切回原步态后：

```text
/robot_gait_state = 32
```

结合项目中已经恢复的状态名称：

```text
6  = stairs
7  = stairs_accumulated
8  = stairs_45
32 = L_walk
```

因此本轮验证的是普通楼梯步态，不是 45 度楼梯步态。普通楼梯切换期间，
地形模式保持 `3`、四边形流保持约 10 Hz、TCP 地形连接保持正常。不能把
本轮 `gait_state=6` 作为 45 度楼梯 `gait_state=8` 的验证结果。

### 8.4 普通楼梯实机上楼验证

原厂遥控器选择“楼梯模式”后进行了实际上楼测试。采集到的
`/robot_gait_state` 共 `5139` 条，全部为：

```text
/robot_gait_state = 6
```

采集中没有出现 `7` 或 `8`。这确认了：

```text
原厂遥控器“楼梯模式”对应普通楼梯 stairs
普通楼梯实际运动全过程保持 gait_state=6
gait_state=6 不是短暂的模式切换中间值
```

本次结果只验证普通楼梯实机上楼，不等同于累积帧楼梯或 45 度楼梯验证。
