# X30 普通楼梯步态接入与测试

日期：2026-07-30

## 1. 目标与边界

在不修改 `RobotHardwareInterface` 三个虚函数的前提下，为
`DeepRoboticsX30` 接入普通楼梯步态，并提供独立的状态闭环测试程序。

本轮只接入：

```text
普通楼梯            gait_state=6
```

尚未接入：

```text
累积帧楼梯          gait_state=7
45 度楼梯           gait_state=8
```

## 2. 官方依据

本地官方资料：

```text
deep_robotics_x30/manuals/绝影X30接口规格书（对外）ros+udp V1.0.4(1).pdf
```

普通楼梯参数：

| 项目 | 官方值 |
|---|---:|
| 遥控源命令 | `0x21010405` |
| 导航源命令 | `0x31010405` |
| 反馈状态 | `gait_state=6` |
| 实心地面模式 | `height_map_mode_state=3` |
| 镂空地面模式 | `height_map_mode_state=4` |
| 无踢面楼梯模式 | `height_map_mode_state=5` |
| 最大前后速度 | `0.3 m/s` |
| 最大左右速度 | `0.2 m/s` |
| 最大转向角速度 | `0.8 rad/s` |

因此普通楼梯不能按 `0.5 m/s` 执行。测试程序会在初始化机器人和发送
UDP 前拒绝大于 `0.3 m/s` 的输入，避免 HAL 静默限幅后造成记录错误。

## 3. HAL 接入

统一动作名：

```cpp
ACTION_GAIT_STAIRS = "gait_stairs";
```

调用链：

```text
上层对象
  -> writeActionCommand(ACTION_GAIT_STAIRS)
  -> DeepRoboticsX30::sendGaitCommand(0x00010405)
  -> motionCode()
  -> 0x31010405
  -> UDP 192.168.1.103:43893
```

X30 适配器在普通楼梯动作生效后，将速度限制为：

```text
|vx| <= 0.3 m/s
|vy| <= 0.2 m/s
|omega| <= 0.8 rad/s
```

未修改：

```text
robot_hardware/robot_hardware/include/robot_hardware_interface.h
robot_hardware/robot_hardware/robot_test_x30_udp.cpp
其他机器人适配器
```

## 4. 测试程序

文件：

```text
robot_hardware/robot_hardware/robot_test_x30_stair.cpp
```

模式：

```text
status       只读检查 ROS1 状态，不初始化机器人，不发 UDP
zero         初始化后只发零速度
stairs       只切换到普通楼梯 gait=6，确认后保持该步态
stairs_move  仅在当前已经是 gait=6 时发送前进速度，停止后保持该步态
walk         只切换到普通行走 gait=0，确认后保持该步态
l_walk       只切换到 L 行走 gait=32，确认后保持该步态
```

步态切换和速度控制已经拆开。`stairs_move` 不再发送任何步态指令，也不会
自动恢复 `walk` 或 `L_walk`。必须先通过 `stairs` 得到
`gait_state=6` 反馈，再单独执行 `stairs_move`。

`stairs_move` 的非零速度联锁：

```text
motion_command_source=navigation
velocity_backend=udp_navigation
basic_state=4 或 16
gait_state=6
height_map_mode_state=3、4 或 5
/plane_seg/quadrangels 为 world 坐标系 XYZ float32 四边形
/plane_seg/quadrangels 持续新鲜且平均不低于 5 Hz
/leg_odom 持续新鲜
速度不大于 0.3 m/s
时间为命令行传入的任意有限正数
精确确认词 CONFIRM_STAIRS_MOVE
```

`/control_mode` 继续读取并记录，但不再按数值提前拒绝速度测试。当前默认
`udp_navigation` 是否真正执行仍由机器人当前选择的速度源决定。

任何一项失效、ROS 退出或速度发送失败时，程序立即发送零速度；只有零速度
发送失败时才把 `ACTION_STOP_MOVE` 作为安全兜底。测试完成后根据 `/leg_odom` 和 `/robot_velocity`
判断是否真的发生运动，不能只凭“命令循环完成”认定成功。

程序不会调用 `ACTION_START_STOP_MOTION`，也不会关闭 105 上的雷达、
IMU、高度图、`plane_seg` 或 `gridmap_port`。

## 5. 已完成验证

Windows 离线回归：

```text
python -m pytest robot_hardware/robot_hardware/tests -q
17 passed
```

106 上已完成普通楼梯静态切换：

```text
切换前：basic_state=4, gait_state=0, control_mode=1
地形：height_map_mode_state=3, quadrangles=6
发送：0x31010405
反馈：gait_state=6
保持：gait_state=6
```

这证明普通楼梯动作映射、UDP 命令和状态反馈链已经打通。

2026-07-31 已完成普通楼梯非零速度实机验证：

```text
请求：vx=0.3 m/s，duration=5 s
发送：250 帧，50 Hz
命令循环：5.00007 s
运行段里程计位移：1.40765 m
平均里程计速度：0.281527 m/s
平均速度反馈：0.274002 m/s
停止保持后总位移：1.56491 m
结果：movement_success=true
```

该结果证明导航速度链、普通楼梯步态和反馈闭环在本次现场条件下能够执行。
`30 s` 曾是测试程序自行添加的安全上限，不是厂家协议要求，现已删除。
命令行 `<duration_s>` 给多少就运行多少，除非状态失效、ROS 退出或发送失败
才会提前停止。

已新增的直接切换实测：

```text
起始：basic_state=16, gait_state=32 (L_walk)
发送：0x31010405
结果：5 秒内没有收到 gait_state=6，运动主机未接受该切换
速度：未发送非零速度
```

测试程序本身没有发送中间 `walk(0)`。旧版本失败日志中的
`0x31010420` 是测试程序主动恢复到 L-walk 的命令。2026-07-31 更新后，
所有自动步态恢复逻辑已经删除；只有显式执行 `walk` 或 `l_walk` 才会改变
到对应步态。

当前实机证据表明，普通楼梯可以从 `basic_state=4, gait_state=0` 成功
切换，但从 `basic_state=16, gait_state=32` 直接切换未被固件接受。这与
规格书“机器人在踏步状态下时切换步态”的条件一致。

## 7. 实机顺序

先通过遥控器进入普通踏步状态，并保持导航模式；操作员持遥控器随时
接管。机器人前方和楼梯两侧必须清空，不可在平台边缘首次测试。

只读和零速检查：

```bash
cd /home/ysc/robot_hardware/robot_hardware/build_x30

./robot_test_x30_stair ../config.yaml status
./robot_test_x30_stair ../config.yaml zero
./robot_test_x30_stair ../config.yaml \
  stairs CONFIRM_STAIRS_SWITCH
```

确认日志出现 `Verified gait_state=6 (stairs)` 后，机器人保持普通楼梯步态。
首次非零速度再单独做短脉冲：

```bash
./robot_test_x30_stair ../config.yaml \
  stairs_move 0.05 0.5 CONFIRM_STAIRS_MOVE
```

`stairs_move` 不会再次切换步态；如果当前不是 `gait_state=6`，程序拒绝
发送非零速度。

短脉冲成功且反馈正常后，执行 5 秒普通楼梯测试：

```bash
./robot_test_x30_stair ../config.yaml \
  stairs_move 0.30 5.0 CONFIRM_STAIRS_MOVE
```

以下命令会被明确拒绝，不发送步态或速度 UDP：

```bash
./robot_test_x30_stair ../config.yaml \
  stairs_move 0.50 5.0 CONFIRM_STAIRS_MOVE
```

`0.5 m/s` 只能在另行接入并验证官方允许该速度的步态后测试，不能借用
普通楼梯模式绕过上限。

需要离开普通楼梯时，显式执行：

```bash
./robot_test_x30_stair ../config.yaml walk
./robot_test_x30_stair ../config.yaml l_walk
```

两条命令都只切换到目标步态，不再自动跳转到其他步态。
