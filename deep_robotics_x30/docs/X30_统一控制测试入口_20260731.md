Date: 2026-07-31

## Result

The four former field-test programs have been replaced by one executable:

```text
robot_test_x30
```

Retired source files:

```text
robot_test_x30_udp.cpp
robot_test_x30_udp_odom.cpp
robot_test_x30_gait.cpp
robot_test_x30_stair.cpp
```

The retired fixed calibration, one-meter open-loop, batch direction, dedicated

interfaces.

## Commands

Read state without sending UDP when built with ROS1:

```bash
./robot_test_x30 ../config.yaml status
```

Send zero velocity without changing gait:

```bash
./robot_test_x30 ../config.yaml zero
```

Select one gait directly:

```bash
./robot_test_x30 ../config.yaml walk
./robot_test_x30 ../config.yaml l_walk
./robot_test_x30 ../config.yaml mountain
./robot_test_x30 ../config.yaml stairs
```

The gait command sends exactly one action. It does not send an intermediate
walk command and does not restore the previous gait.

Send translation and yaw velocity:

```bash
./robot_test_x30 ../config.yaml \
  move <vx> <vy> <omega> <duration_s> CONFIRM_MOVE
```

Examples:

```bash
# Forward at 0.30 m/s for 5 seconds.
./robot_test_x30 ../config.yaml \
  move 0.30 0 0 5 CONFIRM_MOVE

# Rotate at 0.30 rad/s for 2 seconds.
./robot_test_x30 ../config.yaml \
  move 0 0 0.30 2 CONFIRM_MOVE

# Move left at 0.10 m/s for 3 seconds.
./robot_test_x30 ../config.yaml \
  move 0 0.10 0 3 CONFIRM_MOVE
```

The duration is the requested positive finite value. There is no separate
test-duration ceiling. Velocity values remain bounded by `max_vx`, `max_vy`,
and `max_omega` in `config.yaml`. When ROS1 feedback reports ordinary stairs
gait 6, the official ordinary-stairs limits remain:

```text
|vx| <= 0.3 m/s
|vy| <= 0.2 m/s
|omega| <= 0.8 rad/s
```

## Build on host 106

```bash
cd /home/ysc/robot_hardware/robot_hardware
rm -rf build_x30
mkdir build_x30
cd build_x30

cmake \
  -DBUILD_X30_ONLY=ON \
  -DBUILD_X30_ROS1_TEST=ON \
  -DBUILD_X30_PROTOCOL_TEST=ON \
  ..

make -j$(nproc)
```

The output is:

```text
build_x30/robot_test_x30
```

## Docker

The production ROS2 image builds the same source with:

```text
BUILD_X30_ROS1_TEST=OFF
```

The installed executable is:

```text
/opt/x30_robot_hardware/bin/robot_test_x30
```

It can send zero, gait, and velocity commands through the common HAL. The
`status` command is unavailable in that build until the low-frequency factory
state topics are relayed into ROS2.

## Factory directory

`deep_robotics_x30/factory/` is not a runtime dependency and is not included in
the deployment archives or Docker build context. It contains collected vendor
binaries, launch files, disassembly, and plane-segmentation research evidence.
Keep it only as an offline archive; do not copy it to hosts 105 or 106 for
normal deployment.

## Remaining tests

These two executables are build-time checks, not field-control entry points:

```text
x30_udp_protocol_test
x30_factory_contract_test
```

They verify packet encoding and the `RobotFactory` abstraction contract. Users
do not run them for gait or velocity control.
