日期：2026-07-30

## 本轮计划

1. 将 `robot_hardware` 的统一抽象接口和 X30 实现编入 ROS2 Docker 镜像。
2. 保留原有 `RobotHardwareInterface` 三个虚函数，不改变上层调用协议。

4. 明确 ROS1 实机状态测试与正式 Docker 状态反馈之间的边界。




零速度测试会发送心跳、连接确认和零速度，不发送步态切换或非零速度。

## 正式 Docker 架构

控制命令路径：

```text
ROS2 上层算法
  -> RobotHardwareInterface
  -> DeepRoboticsX30
  -> 厂家 UDP
  -> 103/105
```

状态反馈路径：

```text
105 原厂 ROS1
  -> 只读低频状态转发
  -> 106 Docker ROS2
  -> 安全监督
  -> 允许或禁止 action/非零速度
```

当前已有传感器转发只包含：

```text
/lidar_points
/imu/data
/leg_odom
```

正式步态控制仍需补充：

```text

/robot_gait_state
/control_mode
/height_map_mode_state
quadrangels 新鲜度和有效性摘要
```

正式 Docker 不长期依赖 `ROS_MASTER_URI`，也不使用 ROS1/ROS2 bridge
转发高带宽点云。

## 106 动态库冲突与修复

106 首次镜像构建后，`robot_test_x30_udp` 的 `ldd` 结果错误指向：

```text
/usr/local/lib/librobot_hardware.so
```

这是基础镜像已有的另一版多机器人库，不是刚安装到
`/opt/x30_robot_hardware` 的 X30-only HAL。零速度程序因此在进入
`main()` 业务流程、初始化 UDP 或发送机器人命令前退出：

```text
undefined symbol: ACTION_START_STOP_MOTION[abi:cxx11]
```

修复内容：

```text
X30-only HAL SONAME -> librobot_hardware_x30.so
安装程序 RPATH     -> $ORIGIN/../lib
镜像构建检查       -> ldd 必须解析到 /opt/x30_robot_hardware/lib
实机零速脚本       -> 先用 --network none 完成同一检查
```

该修复不修改 `RobotHardwareInterface`、三个虚函数或 X30 UDP 协议。
基础镜像原有 `/usr/local/lib/librobot_hardware.so` 也不删除，避免影响
镜像中其他既有程序。

## 106 路径规范化误报与修复

精简镜像在 106 构建后，`ldd` 已正确解析到：

```text
/opt/x30_robot_hardware/bin/../lib/librobot_hardware_x30.so
```

该路径和 `/opt/x30_robot_hardware/lib/librobot_hardware_x30.so` 指向同一
文件，但旧验证脚本直接比较字符串，因此误报 `wrong HAL library`。
构建、离线验证和零速度验证三个脚本现已先使用 `readlink -f` 规范化
两侧路径，再判断是否加载了正确的 X30-only HAL，并增加静态回归断言。

该误报只影响验证脚本的退出状态。日志已经证明镜像中的协议测试、工厂
契约测试和动态链接本身正确；修复过程中没有发送机器人 UDP 命令。
