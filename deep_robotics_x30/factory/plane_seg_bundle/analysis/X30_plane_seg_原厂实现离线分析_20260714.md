## 5. 已恢复的 GridMap 预处理

`Pass::elevationMapCallback()` 的行为已经由符号和指令确认：

```text
1. 从 GridMap 读取 elevation 图层。
2. 从 GridMap 读取 accessibility 图层。
3. 遍历所有单元格。
4. accessibility > 0.9 时，把对应 elevation 设为 NaN。
5. 将过滤后的 elevation 图层写回 GridMap。
6. 把 elevation 转为点云。
7. 再送入 processCloud()。
```

因此 Docker 复现时不能只对 elevation 做平面拟合；必须先应用同样的 accessibility 屏蔽规则。

## 6. 已恢复的平面拟合主链

`Pass::processCloud()`：

```text
过滤后的 elevation 点云
  -> BlockFitter::setSensorPose()
  -> BlockFitter::setCloud()
  -> BlockFitter::setComputeVerticalPlane(false)
  -> BlockFitter::setDebug(true)
  -> BlockFitter::setRemoveGround(false)
  -> BlockFitter::setMinPoint(20 或 40)
  -> BlockFitter::go()
  -> Pass::publishResult()
```

最小点数规则：

```text
普通情况：20
/height_map_mode == 9：40
```

`Pass::modeCallback()` 只判断收到的 `/height_map_mode` 是否等于 9。它与持续发布的 `/height_map_mode_state=3` 不是同一个数值语义，不能把 state=3 直接当作 mode=9。

`BlockFitter::go()` 的主链与公开项目一致，并增加了 X30 扩展：

```text
VoxelGrid 下采样
  -> RobustNormalEstimator 法向量估计
  -> PlaneSegmenter 区域生长
  -> maxAngleToFloor 约束
  -> RectangleFitter 最小面积矩形
  -> 水平/垂直类型、重心、原始点集扩展结果
```

## 11. 二次反汇编修正与工程落地

本节结论优先于第 6 节中“水平/垂直类型扩展”的早期描述。

`IncrementalPlaneEstimator::tryPoint()` 五参数版本位于 `0x33a98`。精确指令流确认：

```text
iNormal 和 iMaxAngle 在首次读取前被覆盖，原厂实现不使用这两个参数
保留 iMaxAngleToFloor
候选平面必须满足 abs(normal.z) >= cos(iMaxAngleToFloor)
前两个组件点无条件接受
随后继续执行公开版的均方误差增量判断
```

`BlockFitter::go()` 对 `PlaneSegmenter` 的实际配置：

```text
maxError: 0.025
maxAngle: 15 deg，但五参数 tryPoint 中不使用
maxAngleToFloor: 15 deg
searchRadius: 0.08 m
minPoints: mMinPoint
```

`mMinPoint` 默认值为 `20`；`Pass::processCloud()` 在 mode 9 时设为 `40`。该阈值
用于区域生长后的组件点数判断，条件是 `count < minPoints` 时拒绝。

`setComputeVerticalPlane()` 位于 `0x3fe60`，只把值写入成员 `+0x89`。
扫描 `BlockFitter::go()` 的 `0x3fe68..0x425d4` 没有发现对该成员的读取；
`0x40f2c` 和 `0x41148..0x41154` 显示所有 block type 固定为 `0`。所以当前二进制
不能被描述为已经支持垂直平面输出。
